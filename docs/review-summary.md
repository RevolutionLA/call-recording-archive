# 三方代码评审记录（对外版）

> 这份文档记录的是一次"评审 → 复核 → 回复"的完整闭环：外部评审方读代码提问题，开发团队逐条核实后落地，评审方再复核一遍。
> 原则：**不写行号**（代码会动，行号会腐化）、**不写"已修 ✅"这类状态词**（当时的状态不代表现在的状态）。只保留三样东西：结论、根因、防回归清单。
> 涉及的每条改动都已进入主分支，可以在 `src/` 与 `pipeline.py` 里自行核对。

## 一、真 bug：兼容 LM Studio 的声明是真的，但路由拼错过

**现象**：README 与配置注释都说摘要可以走 LM Studio / vLLM / llama.cpp 这类 OpenAI 兼容后端（`base_url` 填 `http://localhost:1234/v1`），但代码曾经把 URL 末尾的 `/v1` 无条件剥掉，于是请求打到 `/chat/completions`，这类服务必然 404。

**根因**：Ollama 的原生接口(`/api/chat`)挂在根路径、兼容接口(`/v1/chat/completions`)挂在 `/v1` 下，两条路的正确拼法相反；当时的实现只做了"去掉 `/v1`"这一步，被两个分支共用。

**修复方向**：探测/原生分支去 `/v1`，OpenAI 兼容分支保留用户填的原始 URL。

**顺带发现的第二个坑**：后端探活失败时把"猜出来的类型"写进了缓存。本机默认地址是 `http://localhost:11434/v1`，Ollama 冷启动那几秒不应答 → 被猜成兼容路由 → 思考模型在兼容路由上返回 **HTTP 200 + 空正文** → 摘要静默退化成"原文照抄"，日志里一声不响。现在探活失败只猜不记，下一通重探；空正文当成失败抛出并记 `error`，下一轮重跑，而不是标成已完成。

**教训**：404 会响，空正文不会。**凡是"静默退化"的路径都必须留日志**。

## 二、误判两条，都记在这里

评审方最初报了一条"GPU 互斥锁让 `--workers N` 并行失效"。核实结论：**并行一直是对的**——子进程带任务清单文件重新进入同一个入口，而锁的判断条件本来就把这种子进程排除在外，只有父进程持锁。评审方复核后自行更正。

第二次反过来：评审方复核开发团队的修复时，把提交说明里写的"按块读切片"当成了代码事实，给一条**当时并未落地**的改动打了通过。开发团队再复核时才发现该文件自上一次提交后没有变化。**提交说明是意图，不是事实。**

两条同源的教训：**判断"改没改"要看这个文件的提交历史，不要看叙述。**

## 三、隐性契约：并行能力靠什么成立

`--workers N` 之所以不被自家锁挡住，只是因为每个 worker 恰好带着任务清单文件重新进入同一个命令行入口，而锁的条件写着"没有任务清单文件时才抢锁"。如果以后有人给 worker 换一种入口（新子命令、直接 import），并行会退化成"只有第一个跑"，**且不报错**。

现在有两个可观测点兜着：

- 被锁挡住的实例以退出码 76 结束（内存熔断是 75），每个 worker 有自己的日志文件；
- 起并行的地方把这层依赖写成了注释。

**排查"并行没提速"时先看退出码，别看 GPU。**

## 四、评审方建议、开发团队照做的防回归清单

1. 认定"已落地"之前，查这个文件的提交历史，而不是读提交说明。
2. 端点/URL 类改动的测试桩必须挂在**真实部署会挂的路径**上（Ollama 答 `/api/chat` 与 `/api/version`，兼容后端答 `/v1/chat/completions`，错路径一律 404）。否则测试会把实现者的错误假设编码进去，自证通过。
3. 探活/健康检查的失败分支不缓存猜测结果。
4. 隐性契约要么写注释要么写测试。
5. 静默退化路径要有日志响应，不只错误路径有。
6. 跨平台分支（Windows 用文件锁、类 Unix 用 flock）至少各执行一次，别只在本机验；本仓库已在模拟的类 Unix 环境下验证过 flock 分支能拿到锁、并在被占用时正确返回失败。

## 五、仍然敞着的两处

- **长段切分的接缝**：超过配置阈值的段落会被切片分别识别再拼回，块间不重叠，压在切点上的字可能丢失。丢字率尚未实测，因此先加可观测性（跑批日志打印块数、接缝处数、每处接缝两端的字），拿到数据再决定是加 0.3–0.5 秒重叠按时间戳去重，还是维持现状。**不建议为了规避它把阈值调大**，那只适合只要文本不要字级时间戳的场景（`--align 0`）。
- **并行收益没有可信数字**：早期记的倍数测于锁逻辑变更之前，未在新代码上复测；README 里已改成带前提的声明（建议 12G 以上显存，本机 6G 保持单 worker）。6G 卡上两个模型会互相溢到提交内存，测出来只会证明"并行更慢"，那不属于架构结论。
